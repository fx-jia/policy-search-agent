# 医保 Search Agent 最终测试交付

三组各95题首轮生成、277份首轮评分尝试，以及8个技术失败组合的一次重跑与评分尝试均已结束。配置、原始结果和用量核验通过；人工终审尚未完成。

**结论：当前自动评分支持 v8.1 明显优于 Native Low；对 Native RAG 尚未证明质量优势。Native RAG 的平均耗时和生成 Token 更低。**

质量分是0—100分的模型评价，不是正确率。只在两个方案都有有效评分的同一题上计算分差；缺失评分不当0。

|比较（前者减后者）|配对题数|平均质量分差|胜/平/负|政策组重采样95%描述区间|
|---|---:|---:|---|---|
|v8.1 - Native RAG|77|+0.016|5/68/4|[-0.511, 0.635]|
|v8.1 - Native Low|77|+13.977|14/61/2|[2.976, 28.208]|
|Native RAG - Native Low|78|+15.048|16/57/5|[3.164, 28.865]|

v8.1相对RAG的区间跨过0，且68题同分，因此不能宣传质量提升。相对Low的差距较大，但仍受单裁判、缺失评分和测试分布影响。此批不能证明在所有真实问题上都有效。

以下成本对比统一使用三方案都成功生成的87道题，生成Token含控制与回答调用，不含离线裁判或Embedding Token。

|方案|平均耗时/秒|P95/秒|每题生成Token|每题观测查询Embedding次数|
|---|---:|---:|---:|---:|
|Native RAG|6.622|10.323|3886.4|1|
|v8.1|9.001|15.632|8127.7|1|
|Native Low|25.81|32.095|6078.7|17|

相对Low，v8.1平均耗时下降约65.1%，但生成Token增加约33.7%。查询Embedding观测调用从17次降至1次；本批实际缓存命中为0，因此不能归因于缓存。耗时受执行顺序和服务负载影响，并非严格吞吐压测。

首轮技术失败：RAG 3题、v8.1 4题、Low 1题，均保留。一次重跑8/8均成功返回答案，6份有效评分均为100，另2份评分无效。没有将重跑覆盖首轮，也没有选择多次中最好答案。重跑成功不等于故障根治或算法质量改善。

首轮评分277份：255份有效、14份裁判输出校验失败、8份连接技术失败。已知有裁判摘录错误及格式问题；这些不是被评答案错误。裁判为deepseek-v4.1-flash，按用户决定未做进一步校准，且与生成模型同属DeepSeek家族。

|---|---:|---:|---:|---:|
|首轮|1,683,535|552,336|120,702|19,108|
|一次技术重跑|47,444|13,825|0|0|

合计已知生成及裁判用量 2,297,140 Token；另有 139,810 Token未结算预留。预留既不是0，也不是已确认消耗；上述总量不含Embedding Token。

首轮人工复核材料含53题（异常/非满分/缺失及随机8题），并另提供重跑的2份评分缺失答案。确认替代引用时核验实际支持性，不按是否命中预标文档判错；人工结论单独保存并统一应用。

可以据此收束当前实验：项目故事有证据支持的是，相比Native Low，受约束的搜索控制在该测试集上获得更高模型质量分、更少查询Embedding调用及更短耗时；不能把它写成全面优于Native RAG。后续任何根据本测试结果设计的新策略，应重新使用独立验证数据。
