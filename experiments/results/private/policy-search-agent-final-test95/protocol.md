# 冻结的95题最终测试

用户决定跳过新增裁判校准，直接执行最终测试。采用原始核心测试划分95题（Easy22、Medium56、Hard17），不追加边界题；与205道开发题按题号及政策组隔离。冻结后不得依据测试成绩修改系统、提示词或量表。

## 方案与调用

- 同期新运行Native RAG、v8.1 A+B、Native Low各95题，共285个正式生成任务；不运行v7、Medium或High。
- 生成模型deepseek-v4-flash-0731非思考，原qwen3.7-text-embedding，固定1000篇、3205块、相同Hybrid参数和统一出站脱敏。沿用已执行配置中的推理源码，运行前校验索引、服务设置及文件哈希。
- 顺序RAG→v8.1→Low，生成全局串行1。此前并发2曾导致检索服务OOM，本次不增加生成并发。耗时仍可能受运行顺序、服务与提供商负载影响。
- 每题限额原样保留：RAG 60秒/2次生成/4次查询向量/35k生成Token；v8.1 60秒/4次生成/3次查询向量/60k生成Token/2次补充动作；Low 90秒/14次生成/24次查询向量/80k生成Token。批次限额为95倍对应单题上限，作为故障保护，不代表预计用量。
- 沿用已有可确认未发送连接失败的有限重连，各物理尝试纳入调用上限。已发送或状态不明的失败不重试，不重跑择优；未知用量保留并检查，不记作0。续跑跳过全部已尝试题。
- 宿主只向隔离运行进程提供题号和题干；参考答案、金标、难度和人工意见不进入生成或控制器。
- 本机Docker中的RAGFlow与检索服务，模型与Embedding使用已授权云端服务，无GPU训练、无重新入库、无模型自动切换。

## 评分与报告

- 冻结原policy-answer-quality-v1量表与deepseek-v4.1-flash裁判，准确性35、完整性25、证据支持25、确定性10、清晰度5，各维0—4。裁判并发4，只读已有输出，不调用Embedding。
- 所有方案同题匿名独立评分，不向裁判提供方案身份、题号、难度、开发分数或人工偏好。预计最多285个评分任务；原系统无有效答案时不发评分请求，评分失败不择优重试。
- 开发5题人工意见保存在开发复核层，不把个案100分或助手推论作为测试覆盖分，也不对测试题另开定向例外。用户明确选择跳过进一步数值校准；报告保留裁判漏评、近似答案评分不一致与同模型家族偏差的限制。
- 主结果采用v8.1对RAG/Low的同题配对质量分差、胜平负、按政策组重采样描述性95%区间、难度分组。保留全部原始分数、缺失和技术失败；不将质量分阈值伪装成整题通过率。
- 对无法评分的答案保留未知范围；技术失败可另记0业务效用，不能混称内容得0分。报告生成平均/P95耗时、已知生成Token、未结算预留、查询Embedding及缓存命中；评分用量单列。
- 所有非满分、裁判关键错误/待审标记、无效评分和技术失败进入复核；另外固定种子抽取8道其余题检查裁判漏判。按题展示所有方案，避免只复核对某方案有利的答案。可能正确的替代引用进入复核，不按不在金标中直接判错。
- 人工复核若纠正语义判断，应用于同题所有等价答案，原始与复核成绩分别报告；不再用这些结果改当前冻结系统。评分修订不称为算法改进。

## 运行与恢复

```bash
PYTHONPATH=. python3 experiments/results/private/policy-search-agent-final-test95/run_test.py prepare
PYTHONPATH=. python3 experiments/results/private/policy-search-agent-final-test95/run_test.py run
```

运行进程使用独立日志与文件锁，宿主start_new_session启动；启动信息写入launch.json。progress.json、各方案records.jsonl和quality/records.jsonl用于恢复。推理原始数据及事件分别保存在rag、ab、low目录，评分记录保存在quality。生成全部完成且出站审计通过后自动评分，最后生成report.md、all_answers.md、metrics.json、review_queue.md；任何未解决的技术中止单独记录。
