## 数据、来源与防泄漏

原始快照 SHA-256 为 `dd052ee5ac20640dcef637eba37624be07fcd2a97f80d2080645ba66d383427c`。来源主键为字符串化 `系统ID`。每题保存问题、原文参考答案、相关文档集合、题型、地区、发布日期、answerable、原始文件行号、正文 Unicode 字符区间及正文摘要。缺失元数据保留 null。

`source_document_id` 在单文档题中记录主来源；多文档题为 null，以 `relevant_document_ids` 为完整正例集合。多文档题的地区和日期不合并编造，逐文档值保存在 `policy_metadata`。`relevant_chunk_ids` 当前为空：重新分块后需要按原文证据重新映射，不能沿用旧 Chunk ID。

首版由助手从10份通知中拟写30题，参考答案直接摘取证据段。`benchmark_reviewed_v3.jsonl`保存30题通过状态，旧候选和v2的两条部分支持意见保留为历史。`expansion_v1/benchmark_150_v1.jsonl`原样包含已通过30题和从40份新来源拟写的120题，新增题为`pending_human_review`。程序校验来源快照、证据区间、正文摘要、重复题号与题目，并检查新问题是否原样出现在主文库；这些检查不能排除语义近重复。

当前完整通过版本为`expansion_v1/benchmark_150_reviewed_v3.jsonl`。用户明确复核通过med-031收窄范围后的修订题，并整体确认其余110题通过；原题的部分支持意见与旧状态保留在v2和快照中。审核通过不自动分配到开发集；修改题意也不能继承旧题的评测分数。

实际划分为 51 题开发、99 题测试。旧 30 题的完整关联组必须进入开发侧，整组分配优先于预定比例。分组包括同源、跨文档比较、近重复候选以及保守的年度筹资、生育保险主题系列；新题的 `question_family_id` 也参与约束。完整规则、版本和局限见[划分说明](<benchmark_split.md>)。

构建知识库时只读原始文档，不读取 Benchmark 问题和答案。开发样本不再用于最终盲测。正式版按来源政策组、同名年度系列和近重复文档分组后拆分 dev/test，同一政策不同问法不能跨组泄漏。相关政策文档作为 RAG 的检索语料存在于知识库是任务所需，不等于把测试 QA 对导入知识库。

当前只有“已知正例”标签。其他政策、解读或 FAQ 可能也能回答，未标记的检索文档不应一概认作不相关。正式测量前，把多种检索方法的 Top 结果做相关性池化复核，补全可替代证据。当前指标是来源检索的初步结果，不是经过穷尽标注的准确率。

当前150题均为answerable=true。不可答题尚未构建，因为需要固定语料范围并人工查证确无充分依据。之后单独报告拒答召回率、错误确定回答率，不把无相关文档题混入 Recall/MRR 分母。

## 实际 API 能力核对

已同时检查本地文档、本地源码和运行容器源码，见 `docs/environment_audit.md`。运行镜像中的检索源码与本地文件不一致。实验适配器采用两边均已确认的接口字段。

| 能力 | 核对结果 |
| --- | --- |
| 检索 | `POST /api/v1/retrieval`，每次一个 question；dataset_ids 可包含多个知识库，但不是批量问题接口 |
| 结果 | `code=0`，`data.chunks`；每块有 `id`、`document_id`、`content`、相似度字段；不能只检查 HTTP 200 |
| 排名 | 以 chunks 数组顺序为排序，适配器补一基 rank；记录 similarity/term_similarity/vector_similarity，字段不一定具有跨方法可比性 |
| Rerank | 仅非空 rerank_id 时加载额外模型；空字符串关闭模型 Rerank，但仍存在内部打分排序 |
| Hybrid 权重 | vector_similarity_weight 可调；ES 初始候选融合与返回阶段混合打分是不同步骤 |
| 关键词参数 | keyword=true 会调用 LLM 关键词抽取；keyword=false 关闭该扩展，**不是关闭全文召回**。HTTP 文档对这个参数的文字描述容易造成误解，运行源码为准 |
| 严格 Dense/纯关键词 | 该公开接口未核实到独立开关；检索入口会创建 Embedding，内部 search 仍构造 matchText+matchDense。向量权重为 1/0 均不能证明另一召回通道关闭 |
| 候选数量 | knn_top_k=向量候选上限；knn_num_candidates=ANN 搜索候选预算；rerank_candidates_count=参与后续排序的候选窗口；page_size=返回窗口大小 |
| 元数据 | metadata_condition 支持显式过滤；首次对照保持无过滤，之后由失败分析决定是否开展过滤实验 |
| 问答 | 当前源码存在 `POST /api/v1/chat/completions`；见 chat_api.py。未实现本项目的问答评测适配，不混用其他版本的聊天字段 |
| 官方 Benchmark | 仓库有 `test/benchmark/` 的 HTTP 客户端与并发性能脚本；检索路由未发现接受问题数组并返回金标评测指标的批量接口。当前脚本负责顺序批量调度和相关性指标 |

代码路径：`api/apps/restful_apis/chunk_api.py` → `rag/nlp/search.py` → `rag/utils/es_conn.py`。源码中 `keyword_extraction` 分支、key_mapping 和模型创建处均已检查。

严格 Dense 通过独立本地适配器实现：在现有容器内复用 `QWenEmbed.encode_queries`，直接向同一 ES 索引发送仅含 KNN 的查询；过滤限制两个知识库、可用状态及冻结的 1,000 篇文档清单，不含关键词、地区或逐题金标过滤。保持 KNN=1024、ANN=2048、返回 64 个 Chunk、余弦阈值 0。通过索引映射核对向量维度与 cosine，并将 ES 的 `(1+cosine)/2` 分数还原为 cosine。旧试验库上 1 题已验证成功，正式开发集使用已冻结的 1,000 篇范围。该方法经本地进程管道调用，Hybrid 两组经 HTTP 调用，初始化分别记录，端到端检索延迟只作部署下描述，不据此推断算法计算效率。

运行版原生 Rerank 将候选分词文本、标题、关键词等送入模型，并把 0.7 的词项分数与 0.3 的 Rerank 分数混合。相较无模型排序分支，它还改变了词项重复权重，因此这是框架两种配置的对照，不能声称只增加一次模型排序的严格单变量消融。后续若要隔离纯重排收益，需冻结完全相同的候选列表再独立重排。

## 本地流程验证与正式对照的边界

本地方法是 Python 标准库实现的中文双字 BM25：中文连续片段取双字，ASCII 取词/数字；按 600 个 Unicode 字符切块，无重叠，每块打分加入文件标题。包含全部 3,081 篇原始主文及原始标题，得到 8,094 个块。附件未索引，坏标题与短正文未在本轮自动修复，问答候选未入库。

这是便于离线验证的检索器，不是 RAGFlow/Elasticsearch 的 BM25 配置，也不是 Dense、Hybrid 或算法创新。它与部署的 512 Token 分块不同，因此不能把离线分数直接与后续 RAGFlow 分数混为同一受控对照。

固定设置：候选返回窗口 64 个 Chunk，文档评价 K=1/5/10，预定上下文为前 5 个 Chunk；目前不调用生成模型。BM25 k1=1.2、b=0.75，未针对这 30 题调参。

RAGFlow 适配器请求 page=1、page_size=64、rerank_candidates_count=64、knn_top_k=1024、knn_num_candidates=2048，禁用关键词扩展、跨语言、KG、TOC、知识编译块。正式入库时还须关闭父子替换、自动问题/关键词等会改变候选内容的配置，或在所有方法中一致启用并记录。

API 只提供最终返回结果，不能完整还原 Rerank 前内部初始集合。因此返回窗口 Recall **不能**被宣称为内部候选召回率；仅凭一次 API 响应无法可靠区分 Retrieval Failure 与 Ranking Failure。后续需要可追踪的阶段输出，或固定候选集后独立重排的设计，再决定是否有必要增加小范围适配。

## 文档映射与指标

RAGFlow 分配的 document_id 通过导入清单映射到原始系统ID，不按标题猜测。映射文件需包含 `source_sha256`、`knowledge_base_version`、`dataset_ids` 和 `documents`（RAGFlow document_id → 系统ID 字符串）。启动前核对版本、知识库和所有正例是否已入库。返回未知文档 ID 时明确记为错误；不会静默丢弃它并抬高指标。请求不会使用当前题的正例 document_ids 过滤检索范围。当前两个物理知识库中存在重复和未解析文件，因此每次请求都使用完全相同的 1,000 篇 document_ids 清单，仅用于限定已冻结的整个评测语料。

设相关文档集合为 R，返回 Chunk 窗口按文档首次出现去重得到 D：

- Recall@K = |R ∩ D[:K]| / |R|。
- Hit Rate@K = 1[|R ∩ D[:K]| > 0]。
- MRR@10 = 第一个相关文档在前十的倒数排名，未命中为 0。
- nDCG@K 使用二值相关性与 log2(rank+1) 折扣；当前仅能解释为已知正例 nDCG。
- `context_document_recall@K_chunks` 不先去重，直接取前 K 个 Chunk 后检查覆盖多少相关文档。
- `returned_window_recall` 只指返回窗口内已知来源覆盖，不是内部候选阶段的 Recall。

同一文档多个 Chunk 不应重复算成多个相关文档；文档命中也不保证命中了答案所在段。比如正确文档的前言与正文答案属于同一文档，却不一定同等支持回答。下一阶段可用本地证据 offset 判定证据区间覆盖，RAGFlow 下需绑定分块版本和实际内容。

含“本通知”等指代的答案句，还要检查最终上下文能否确定政策身份。人工预览显示的来源标题、索引打分使用的标题、模型实际收到的标题是三个不同环节。运行容器有将文档名称字段拼入Prompt的代码，但该字段不一定是原始政策标题；标题和元数据需要通过实际入库与上下文记录确认。新增背景证据用于审核，不按金标强制注入检索或生成流程。

所有有效有答案题参与宏平均，包括 API/解析/映射失败的零分；失败另报错误数。全失败的运行不能称作完成了有效性能测量。并列 BM25 分数按 Chunk ID 稳定排序。P50/P95 使用排序样本线性插值，延迟仅统计成功查询，不包含建立索引、写报告和人工审核。

## 结果与后续问答评分

每次运行建立不覆盖已有目录的 experiment_id，保存 manifest.json、per_query.jsonl、summary.json、report.md。manifest 记录数据与代码摘要、知识库版本、RAGFlow 镜像/源码依据、模型、分块、检索/生成配置、执行时间、环境及使用题目清单。

结果保留 Chunk ID、来源 ID、排名、分数和本地偏移，不默认保存未知返回正文或服务错误原文。凭据只通过环境变量读取，不写配置或结果。HTTP 测试使用 mock，仅验证接口契约，不冒充真实 RAGFlow 推理。

以下为早期检索阶段记录；最新生成诊断见本文开头。该早期阶段 QA 指标及成本均为 null / Not Run：未实现/未运行 Exact Match、F1、Answer Accuracy、Faithfulness、Citation Accuracy、端到端生成耗时和生成 Token 统计。Dense 查询 Embedding 已记录提供方实际报告的2,117个Token，原生HTTP组用量不可得，不能推算账单总量。后续先为数字题审核“金额/单位/年度/人群/地区/比较符”答案槽位，再设计匹配，不能只比孤立数字。开放回答的人工/Judge 评分需固定规则及评测模型并记录依据。没有实际 Token 和可靠价格时不估算成本。

## 早期开发阶段的实验次序

以下保留早期开发任务顺序，完成状态以上方最新记录为准。150题审核、51/99分组、1000篇已有索引冻结及开发侧三组首次基线已完成。严格Dense已实现，gte-rerank-v2已经实际调用；原生Rerank有11次传输错误，原始记录保留。扩库保持暂停。

1. 复核三组Top5池化结果，优先处理已发现的替代正例；将新标签另存版本，用相同已保存排名本地重评，不能只改有利于某方法的标签。
2. 核对核心答案块覆盖，区分排序不足、分块边界、辅助背景缺失与整段字面匹配误报。已完成首轮诊断，见错误分析。
3. 依据真实缺口设计有限的文档内证据补全，在相同候选及Token预算下验证。实现前明确规则与消融变量，不按逐题金标补块。
4. 将Rerank传输稳定性修复与算法实验分开；原生配置比较不能代替冻结候选的严格重排消融。后续真实调用需继续遵守额度约束。
5. 完整方法、标签和参数冻结后才开展99题正式测试；10题开发生成评分已完成，不能替代最终测试。
