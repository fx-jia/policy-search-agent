# 子问覆盖复查的41题扩验

2026-09-23。**这版“看初稿后自查子问”的方案没有表现出净收益，停止扩展这一版本，不接入默认链路。** 首轮10题中补回med-116的现象没有推广到这批题；不能将两轮不同题目、不同日期的数字拼成同期提升。

## 验证范围及控制

使用开发51题排除前轮10题后的全部41题，覆盖6个政策组；不按生成错误挑题，不运行原99题。沿用qwen3.7-flash、temperature=0、seed=20260921、1200输出Token上限以及原提示模板。复用已有Dense64＋boundary2560上下文，115个选中片段完成本地检查及脱敏。没有新增Embedding、入库、检索或Rerank。

每题先生成共同初稿，再分别进行普通复查和子问覆盖复查。两个复查分支读到同一问题、证据、初稿，互不看到对方输出。74项评分要点及多/单要点分组在生成前冻结；语义评分由助手逐题检查，**不是独立人工验收**。

用户明确批准41题、最多123次调用后开始执行。实际121次调用，119份可解析回答，2次TLS EOF失败。med-044初稿失败导致两个复查分支跳过；med-088普通复查失败。无重试，均保留41题分母；引文无效的回答仍保留并分别评价正文与引用。

总物理账单口径：提供商报告257,580 Token，其中输入227,155、输出30,425；119次有用量、2次失败用量未知，不能称完整计费用量。上表复查列均包含共同初稿，不可相加当实际账单。子问方案已知Token约为单轮的2.33倍、普通复查的1.09倍；成功同题生成耗时约为单轮2.07倍。未测实时检索及前端开销。

## 每条结果差异对应什么

| 题号 | 观察 | 解释 |
| --- | --- | --- |
| med-019 | 初稿和子问复查拒答，普通复查给出完整参保条件 | 普通复查有一次内容修复；子问版本没有修复。所给E1有0至7周岁、父母就业缴费、居住证条件及2026年度缴费语境，另有旧政策干扰。 |
| med-022 | 初稿和普通复查正确，子问复查增加“苏医保规〔2021〕号” | 所给材料没有该文号，且编号缺少序号；属于明确的无依据新增事实。正确日期仍在，也不能忽略附加错误。 |
| med-042 | 子问复查删除了“财政预算单位产假工资与津贴不重复发放” | 按冻结第四要点记遗漏；该要求可能超出题干仅问“是否同样调整”，必须给出评分敏感性分析，不能把它当毫无争议的退步。 |
| med-088 | 普通复查TLS失败，子问方案成功 | 只是服务返回差异，不是子问算法修复了一题。 |

与初稿相比，子问版本没有任何评分要点从错变对；唯一要点变化是med-042第四项从有到无。两次完整有据退步为med-022与med-042。普通复查则补回med-019三项条件，但med-088连接失败造成主分母上的一得一失。

**没有修复的明确缺口也要记录。** med-006仍漏掉中断缴费期间个人账户按规定划拨；med-115仍未回答徐州具体10%费率，而以省级8.8%示例替代。两题所给证据都含目标内容，子问检查仍标成covered。另有med-009引用了错误E编号、med-015拼接非连续原文，复查均没有清除这些问题。

子问输出40份中35份coverage格式合格，但格式合格不代表判断正确。30/40份最终answer与初稿完全一致；其中大量初稿原本正确，不能仅凭重复率证明模型存在“锚定效应”。结合上述漏检案例，可以提出“依赖初稿进行自查不够可靠”的假设，仍需新的对照验证原因。

## 评分敏感性与责任边界

本轮冻结rubric由助手根据已审核题干和原文细化，发现两个可争议的额外要求：med-002把申请承诺书纳入“能否先备案”要点；med-042把“不重复发放”纳入“财政单位是否同样调整”要点。保留原评分作为预先口径，另做**事后敏感性分析**，不覆盖原文件：

| 口径 | 初稿完整有据 | 普通复查完整有据 | 子问复查完整有据 |
| --- | ---: | ---: | ---: |
| 冻结严格口径 | 31/41 | 31/41 | 29/41 |
| 不强制上述两个附加要求 | 32/41 | 32/41 | 31/41 |

放宽后子问版本仍没有净增；med-022的无依据文号及med-019的拒答未纠正不依赖这两项争议。med-008/025的claim将“基本医保金额＋长护险”写成“其中包含长护险”也按三组统一判为关系错误；正文合计数字仍给内容点。若今后调整这种表达的宽严程度，需对三组一致重评，不能只改某个方案。

这是一次开发侧、单次生成、助手复核的实验。题目来自已有开发政策组，不是新政策组盲测；原99题也已被查看，不能再次调到好看后当最终确认集。

## 后续取舍及复现

按事先的净增条件，这个版本不继续扩大调用，不修改默认CLI或RAGFlow网页。可以如实记录一次失败消融：引入额外自查，成本提高但没有净收益，因此未采用。不能写成“多子问模块提高准确率”。

下一种值得小规模验证的设计是：**先独立确定待答事项，再为每项对应证据，最后统一生成**，将检查从“读完初稿后追认”改为生成前的明确约束。先用开发材料离线检查事项覆盖和证据映射，再决定模型调用；这只是后续待验证方向，本轮没有实现或宣称有效。

相关29项测试和ruff通过，独立离线审计核对123条计划记录、121次请求、234条引文及所有评分计数；4份报告产物离线重算完全一致。冻结输入未修改，未额外调用模型进行评分。
