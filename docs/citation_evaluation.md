# 引用格式优化：同期10题对照

本轮使用qwen3.7-flash，对相同10道开发题、相同Dense boundary上下文重新运行两种引用格式，各10次，共20次实际请求，全部成功。助手按调用前冻结的答案要点及实际片段复核后，**答对且忠实、引用完整有效的题数从1/10提高到9/10；完整答对仍为9/10。**

| 指标 | 旧格式 original_ids | 短编号与约束 short_ids |
| --- | ---: | ---: |
| 有效回答 | 10/10 | 10/10 |
| 完整答对 | 9/10 | 9/10 |
| 正确答案要点 | 17/18 | 17/18 |
| 答对、忠实且引用完整有效 | 1/10 | 9/10 |
| 回答忠实于所给上下文 | 9/10 | 10/10 |
| 引用ID属于当前输入 | 3/22 | 21/21 |
| 引用ID正确且原句匹配 | 2/22 | 21/21 |
| 有效引用支持的claim | 2/18 | 17/17 |

结果仅适用于已看过的10道开发诊断题，语义评分由助手完成，尚未独立人工复核。引用数量和claim数量由模型输出决定，因此同时报告按题统计，不能只看引用条目百分比，更不能声称整个系统达到100%可靠引用。

## 具体改了什么

旧输入把两种编号放在同一行，例如：

```text
[source=83700; chunk=35d2648f93ae18ca]
政策正文……
```

模型经常把整串`83700; chunk=35d2648f93ae18ca`或来源ID填入要求精确Chunk ID的字段。本轮改为：

```text
可用chunk_id：E1, E2, …
同一文档的片段分组：[["E1", "E2"], …]
[chunk_id=E1]
同一份政策正文……
```

模型只需返回`"chunk_id":"E1"`。每次请求在本地保存E编号到真实Chunk和来源的映射，不向模型同时暴露两类可混用的编号。同源分组保留了片段之间的关联；片段正文、数量与顺序全部保持不变。

同时明确三条输出约束：编号从当前列表逐字复制；引文必须是该片段中的连续原文，不能用省略号或拼接代替；回答中的每项事实都应有对应claim和证据。跨块依据可分成多条引用。

引用检查继续沿用原标准：精确编号必须存在，原句在对应片段中规范化匹配，忽略空白及HTML表现差异；之后另行检查语义支持性。没有把错误编号自动截短、删除省略号或补写答案来提高分数。新增映射仅解析合法E编号。

这是生成提示与引用格式的工程优化，不涉及训练、Embedding、检索排序或上轮上下文补全算法的修改。实验比较的是“短编号＋明确约束”整体方案，不能单独断言收益全来自短ID或某一句指令。

## 代表性变化与退步

| 题目 | 旧格式 | 新格式 | 解释 |
| --- | --- | --- | --- |
| med-001：两类人群缴费标准 | 答对，但大学生引文插入省略号 | 答对且两条连续原文引用有效 | 修复引文改写 |
| med-017：退休账户金额 | 答对，但引用ID混入来源编号 | 答对，以E1正确定位 | 修复ID混用 |
| med-043：两项最低筹资标准 | 答对，跨块证据ID均错误 | 用E1、E2分别引用相邻块 | 保留跨块联合依据 |
| med-026：医疗救助对象缴费由谁负担 | 混淆通知发布年与缴费年度后拒答 | 正确回答医疗救助基金全额资助并引用原句 | 本次答对，但没有新增发布时间信息，不能认定年份问题已解决 |
| med-116：生育待遇与基金支付 | 三个子问均答对，引用ID错误 | 引用全有效，却漏了职工生育待遇资金来源这一子问 | 答案从3/3要点退步到2/3，保留为失败 |

按答案正确性成对比较：med-026改善、med-116退步，其余8题不变，所以两组都是9/10。按“完整有据的正确回答”比较：8题改善、0题退步，med-117原本就通过，med-116因不同原因两组都未通过。

med-116揭示另一层区别：**回答中已经写出的事实都有证据，不代表问题要求的事实都答全了。** 当前`all_answer_facts_in_claims`检查前者，冻结的答案要点评分检查后者；不能用引用有效率替代答案完整性。

## 对照为什么可比

沿用相同10题、固定的45个片段（29份公开政策来源）、相同上下文选择和顺序、同一模型与解码参数。每题交替提交两组，旧格式Prompt与上一轮boundary完全一致，但本轮重新请求，未拿历史响应冒充同期控制。两组都未改写query或添加政策日期，99道测试题没有使用。

两组问题和正文一致，不代表整个Prompt等长：新格式增加了约束与编号列表。供应商报告的输入Token均值为1596.6→1646.1；总输入15966→16461，输出2973→2188，两组总量分别18939和18649，本轮合计**37588 Token**。输出较短是本次观察，不能保证以后同样省Token。

成功生成平均耗时约4.54→3.57秒；各仅10次，且请求按序交替，无法单凭该结果宣称算法加速，也不是RAG端到端延迟。无额外Embedding、检索、Rerank、模型重试或答案修复调用。

本轮不重新调提示或挑样本。非日期模型名、单次生成和定向选题均限制结论；温度0并不消除全部输出波动。旧控制组与上轮存在措辞和claim划分差异，原始输出均保留。

## 下一步与面试追问

优先针对med-116验证多子问覆盖约束：在生成前明确需要回答哪些子问，逐项回答后检查是否遗漏；只从问题提取需求，不把参考答案注入Prompt。该方案尚未实现。政策标题/发布时间信息仍需独立验证，尤其不能用本轮med-026一次答对代替元数据质量检查。完整方案冻结前，暂不启动99题最终测试。

可用于面试的表述：“我从真实输出中定位到文档ID与Chunk ID混用、引文被改写等问题，设计请求内短证据编号、来源映射与连续引文约束。在固定上下文的10题同期对照中，助手复核的完整有据回答从1题提高到9题，同时完整答案保持9题，并记录了一道多子问漏答退步。该结果是开发诊断，尚未推广为测试集准确率。”

1. 为什么引用能在原文中找到，仍不能证明回答正确？
2. 短ID如何映射回真实来源，为什么映射必须限定在当前请求？
3. 两组答案都为9/10，为什么还要看逐题改善和退步？
4. 本实验能否证明单独缩短ID就有收益？要怎样进一步拆分验证？
