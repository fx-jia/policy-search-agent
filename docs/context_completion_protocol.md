# 离线上下文补全实验 v1

本协议在计算补全效果之前冻结。来源为已完成的51题开发集检索和审核；不运行99题测试集，不调用Embedding、Rerank或生成模型。已观察到开发集案例，因此这是开发实验，不是盲测。

## 假设和对照

假设：命中文档后，提升同文档相邻块的上下文优先级，可以减少政策规则跨块截断。反例：补入背景挤走另一文档中的关键证据，或加入同文档中不回答问题的内容。

三组共享每题保存的64个候选及其内容、顺序、原始排名。每组预算为2560 Token，原排名前三块可作为补全种子。按完整块装入；放不下则跳过并继续，不截断块、不递归扩展、不从64块以外补入。先尝试后块，再尝试前块。

1. ranked：只按原排名装入。
2. neighbors：装入前三名种子时，优先尝试同文档直接前后块。
3. boundary：同上，但仅在种子末尾无句末/分号/冒号标点时补后块；前块末尾无这些标点时补前块。忽略空白和尾部引号/括号。这是简单可审计启发式，不宣称准确的语义边界检测。

neighbors 对 ranked 检查补块机制；boundary 对 neighbors 检查边界约束。只运行这套预定参数，不根据本轮结果扫参。失败请求仍为空上下文并计零，不靠重试美化Rerank结果。

## Token和公平性

采用容器已有缓存的 tiktoken/cl100k_base，对每块 `[source=ID; chunk=ID]\n正文\n\n` 独立编码并求和，含来源头。它是固定上下文预算的参考口径，不是Qwen账单Token、完整生成Prompt长度或拼接全文一次编码的精确长度。预算相同不保证实际装满，报告实际平均Token和块数。

与旧Top5实验的区别是“固定块数”改为“固定预算”；只能把新ranked作为这轮优化的直接对照，不能把预算变化算作补全收益。

## 评价口径

主指标：原始参考证据完整覆盖题数。按来源与原始顺序拼接**连续且已选中的**块，去HTML标签和空白，检查每条原始参考证据是否完整出现。不能跨来源或跨漏掉的块拼接。所有参考段均覆盖才计一题完整。另报平均参考段覆盖率。

这不是生成回答正确率：原参考段可能过长或带辅助背景。分开报告已人工确认的替代证据：med-001可用79272同义段替代；med-027可用79343的津贴段替代原通知的津贴段，但仍须保留81200的2026年适用背景。不会修改原benchmark。

成本指标：实际Token、块数、来自已审核“不支持”文档的Token占比；“部分支持”和“未审核”单列。仅有20个问答—文档配对经过补标，不能把未标正例的内容全部视作无关，也不能把同一正例文档的所有块视作有效答案。

按6个政策组进行配对bootstrap（固定种子20260921，2000次）估计完整覆盖率差值的探索性95%区间；组数很少，不据此宣称泛化能力。报告新增覆盖和退步题，保留负结果。

## 可复现与隔离

只读导出已有1000文档/3205块，验证markdown顺序字段、映射、块数和索引序列号。导出不导入任何模型封装，只读MySQL/ES与本地分词器缓存。缓存包含本地原始正文，按private数据管理；不输出来源79870的个人内容。

选择模块只接收候选文本、来源、顺序、排名、Token计数，不读取问题答案、金标或评测证据。先保存所有选择，之后评价模块才能读取金标。输入、脚本、配置和结果均保存摘要。99题测试文件仅作字节摘要完整性检查，不解析题目或运行测试检索。
