# Benchmark构建说明与面试讲解

核对日期：2026-09-21。当前150题已全部获得用户审核通过，正例来源共50份文档；med-031采用已复核的范围修订版。原30题已经用于开发，派生版本已按政策关联组冻结为 51 道开发题、99 道测试题，见[划分说明](<benchmark_split.md>)。实时状态见[审核进度](<benchmark_review.md>)，选文方法、规模依据和分组计划见[150题扩展说明](<benchmark_expansion.md>)。

## 实际构建流程

原始政策语料 → 全量数据诊断 → 定向选取证据 → AI辅助拟题 → 程序提取原文与标注来源 → 人工审核 → 保存版本 → 固定协议评测。

题目由AI助手阅读本地原文后拟写；首批问题与证据段落位置保存在`experiments/datasets/private/question_specs.json`，新增120题保存在同目录的`expansion_v1/question_specs.json`。`build_benchmark.py`读取清单，负责取证、验证和组装JSONL，并不调用模型自动生成问题。没有额外调用付费出题API。用户负责审核问题、证据与参考答案的一致性。

## 原始数据与出题来源

原始JSONL包含3,081份文档，有政策正文、系统ID、来源路径及地区、日期等元数据，没有现成的独立评测题、参考答案或相关性标签。数据分析检查了解析、空值、短正文、重复、标题异常、话题树对齐和隐私候选等问题。分析报告不会自动清洗或替换原文。

首轮定向选取10份具有可定位政策规则的通知，覆盖江苏省、苏州、徐州的缴费、待遇、异地备案、个人账户与生育保险等内容。选择依据是方便逐条核对证据和验证多种问题结构；选文依赖阅读判断，尚未实现自动抽样器，也没有按真实用户咨询频率做统计抽样。

首批出题来源是10份政策，扩展后是50份文档；早期本地检索范围是全部3,081份主文。当前真实检索因额度限制复用已有1,000份来源，固定整个语料的文档清单；不会按每道题的正例ID缩小检索范围。已在旧30题及同组21道新增题构成的51题开发集完成三组基线，其余99题未运行，见对照报告（本地归档：`docs/baseline_comparison.md`，未收入本备份）。

## 先确定证据，再拟写问题

先定位原文中明确表达规则的段落，再拟写与该段落匹配的问题。题目尽量明确地区、政策年份、人群和条件。需要两段才能回答时保留两段证据；需要比较两份政策时保留两份来源。

首批30题的题型统计（150题统计见扩展说明）：

| 主标签 | 数量 |
| --- | ---: |
| 数字查询 numeric | 9 |
| 条件限制 conditions | 12 |
| 政策时间 policy_time | 5 |
| 多段信息 multi_paragraph | 1 |
| 办理流程 procedure | 1 |
| 同地区跨年比较 policy_version_comparison | 1 |
| 跨地区跨年比较 region_time_comparison | 1 |

这些是由助手逐题指定的主标签，尚不是严格互斥、经多标注者验证的问题分类体系。共28道单文档题、2道双文档题；30题均为有答案问题。

## 参考答案与相关性标签

参考答案由指定的原文证据段直接拼接，不采用被测检索器或聊天模型的回答。当前参考答案可能包含完整段落和额外条件，适合作为审核依据；未来进行答案准确率评测时，还要整理答案要点或结构化槽位，不能直接拿整段原文要求模型逐字输出。

每道题保存：question_id、question、reference_answer、relevant_document_ids、question_type、region、policy_date、answerable，以及evidence、review_status等信息。

原始系统ID作为稳定来源主键。每段证据还保存JSONL文件行号、正文中的[start,end)字符范围、段落索引、正文SHA-256和原始URL。字符范围按Python Unicode字符计数，不是字节或Token。

来源ID稳定于这份上游数据快照，正文摘要则绑定具体内容。原文发生变化后，不能只凭相同ID继续沿用旧偏移。RAGFlow document_id需要另建上传映射；Chunk ID依赖分块版本，当前relevant_chunk_ids为空，不伪造关联。

已标注的来源属于已知正例，即`qrels_scope=known_positive_documents_only`。其他通知、解读或FAQ也可能提供同样有效的答案，尚未对全库相关性作穷尽判断。未来要合并多个检索方法的返回结果，人工补标其他有效证据。

## 一个真实例子

med-005的问题是：“苏州2026年度学生儿童居民医保的筹资标准和个人缴费标准分别是多少？”

原始来源为系统ID83468，在JSONL第548行。证据分别位于正文[204,284)与[285,363)：第一段包含学生儿童筹资标准每人每年1040元；第二段包含个人缴费标准每人每年390元。因此该题标为multi_paragraph，相关文档集合为["83468"]。

该文发文日期字段为2025-09-29，问题询问的是2026年度标准。发布日期与规则适用年度必须分别理解，不能因为发文于2025年就覆盖问题中的2026年。

med-029比较徐州2022年与2024年的普通居民缴费标准，正例为79273、79320两份文档。只返回其中一份时，该题的文档Recall是0.5，而Hit Rate可以是1。该题已获用户审核通过。

## 程序校验与人工审核各自解决什么问题

程序会校验原始文件摘要、来源ID是否存在、证据坐标是否有效、证据文本是否与正文完全一致，以及每个正例是否附有证据；构建过程中对证据进行基础隐私规则筛查，并拒绝原样存在于主文库中的完整问题。

这些检查证明的是来源和数据结构可追溯，不能自动证明题意完整、条件一致、政策解释正确或相关性标签完备。人工审核负责核对问题与原文的语义关系，包括年份、地区、人群、金额单位和限定条件。

2026-09-21用户先确认28题通过、2题部分支持；两题补充背景证据后确认通过，首30题完整通过版本为`benchmark_reviewed_v3.jsonl`。扩展后，第31～40题先获9题通过、med-031部分支持；随后用户明确确认med-031修订稿及其余110题均通过。最新完整版本为`expansion_v1/benchmark_150_reviewed_v3.jsonl`，确认事件为`review_completion_v1/receipt.json`。原始候选、历次审核、预览快照和历史实验均保留。通过状态来源于用户明确确认，不是程序校验或助手自行判断。

## 防泄漏与当前局限

知识库读取原始政策主文，不导入新构建的评测问题或参考答案。参考答案取自原始证据，不取自被测系统输出。程序做了完整问题的精确重复检查，但没有完成语义近重复检查；原始语料中的FAQ也可能与评测题接近。

原30题保留split=smoke，已经用于开发验证，不能在后续调参后当作未见过的最终测试集。原始审核版本中的新增 120 题保留 split=candidate；派生划分已依据来源、题族、近重复候选和保守政策系列完成分组。旧 30 题所在整组共 51 题进入开发侧，其余 99 题留作测试。测试题尚未运行检索。

当前主要限制是：定向选文而非真实用户查询抽样，同文档题目相互关联，相关性只有已知正例，无不可答题，未单独读取附件字段构造题，独立留出的 99 题尚未用于检索实验。少数正文已包含上游拼接的附件文本，这仍属于当前主文字段，不能宣称做过独立附件检索。当前真实基线只反映1,000篇固定语料上51道开发题的已知来源检索效果。

## 当前阶段可用于面试的表述

项目采用证据驱动的Benchmark构建方法。先分析3,081份医保文档的结构与质量，从10份通知中通过AI辅助拟题构建30题，再按地区和业务主题定向选择40份新来源，扩展到150题。参考答案直接取原文，保存来源ID、证据字符偏移和文件摘要，由程序验证来源一致性、人工验证语义支持。人工审核发现两题背景信息不足和一题问题范围过宽，经补充背景、收窄题意并复核后，150题全部通过。随后按政策关联组冻结为 51 道开发题、99 道测试题，已暴露的题及关联题全部进入开发侧；全库相关性补标仍待完成。在1,000篇固定语料上完成了51题开发集的真实检索对照，同时保留早期离线验证记录；这些结果不能代表150题或端到端问答效果。

可以说“150题已完成问题、给定证据与参考答案的一致性人工审核”。不能据此称为“分层随机抽样得到成熟Benchmark”“全库相关性标注完备”“已彻底消除泄漏”或“实现了问答准确率提升”。

## 本轮面试追问反馈

1. 题目措辞贴近原文的偏差，可以通过保留原意的同义改写、用户自然问法等方式缓解，但不能保证消除，也不能解决选题来源过窄。改写不得丢失地区、年份、人群和数值条件，必须重新审核。原题与改写题应共享question_family_id，放在同一开发/测试分组，分别报告两组效果或按题族聚合，不能把30题加30个改写当成60道独立问题。当前文件中尚无已实现的改写扩充版，不能在面试中说已经做完。这属于评测集的表达变体构建，与在线检索前的Query Rewrite模块需要分开说明。
2. 其他文档可能是同样有效的答案依据。遗漏这些正例会低估效果，所以要对多个方法的返回结果做池化审核并补标，所有方法用同一冻结标签版本重评。补标后的Recall分母也会增加，因此不能保证分数一定上升；同主题但年份、地区或条件不同的文档不能直接认定相关。
3. 控制变量能增强实验归因，但不能排除在同一批题上反复试参数的过拟合。应先按来源政策组/近重复簇/题族划分开发集与独立测试集；在开发集确定参数，冻结方法后才评估测试集，不根据测试分数继续挑方案。消融时只改变待研究模块或参数，保持其他条件一致。存在随机性时重复实验，并按文档组/题族考虑置信区间，避免把同源题当成完全独立样本。当前30题已参与开发验证，不能回头声称是未见测试集。

## 面试追问练习

1. 为什么先选证据再出题？这种方法可能引入哪些题目分布偏差？
2. 既然已经知道答案来源，为什么还需要对其他检索结果补充相关性标注？
3. 文档级命中与答案所在片段命中有什么区别？
4. 重新分块、更新原文、换RAGFlow知识库时，哪些ID或证据坐标可以保留？
5. 怎样从这30道开发题扩展为可以公平比较算法的正式测试集？
