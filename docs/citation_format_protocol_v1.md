# 引用格式优化：同期成对开发诊断

## 问题与方案

上一轮qwen3.7-flash生成中，47条引用有41条使用了错误ID，6条引文插入省略号，另有正文事实没有对应claim。用户已同意进入下一步修正引用格式。本轮是已有评测流程的小范围修改，复用固定上下文和评分器。

两组均使用此前10题的Dense boundary上下文：原样保存的片段、顺序、相邻关系及问题不变，不补发布时间等元数据。不改变检索、选块、模型、解码参数或答案要点。只比较以下引用表达方案：

- original_ids：逐字复用v3的原始Prompt，输入头同时呈现source和chunk。
- short_ids：每次请求按输入顺序分配E1、E2等短编号，提供可选编号列表与同一文档分组；仅E编号用于chunk_id。明确要求连续原文摘录、不用省略号或拼接、跨块证据分条列出，并检查正文每项事实均有claim。

映射表仅用于本地将有效E编号还原为原始Chunk及来源，模型不会收到原始长ID。有效性检查仍要求本次输入中的精确编号和规范化后的连续原文，不纠正模型输出中的空格、前缀或省略号。模型的原始响应原样保存。验证器能发现格式错误，但不能代替语义支持性判断。

本轮比较的是“短编号＋明确引用约束”的整体方案，不单独归因于短ID或某一句提示。输入正文完全一致，Prompt头及指令长度有差异，按供应商实际Token报告这一开销。

问题仍为med-001、017、018、026、029、030、043、090、116、117。每题两组都重新请求，交替提交顺序，形成同期20次调用；上一轮结果只作历史对照，不取代本轮控制组。模型qwen3.7-flash，temperature=0、top_p=1、seed=20260921、max_tokens=1200、JSON对象、非思考模式，端点和供应商连接不变。

出站正文来自之前逐项查看的公开政策片段允许列表；再次验证原文及清理后摘要。继续排除来源79870、删除79804联系信息和网页/图片链接。本次两组只有引用编号与指令变化，不新增原始正文。prepare与run均从冻结开发题、索引快照和选择记录重新构建请求，任一问题、片段、映射或Prompt不一致都在加载凭据前拒绝。

## 评分与判定

继续使用调用前已固定的18个答案要点，数值、单位、对象、年份、地区和范围限定都需匹配；不能只匹配关键词。助手检查全部成功回答，并记录每项评分理由，不称作独立人工评测。

主要观察“答对且忠实且全部事实有有效引用”的题数。分开报告答案正确数、正确要点数、忠实性、引用ID有效率、ID与原句同时通过率、语义支持率，以及未引用事实、错误编号、引文改写、年份混淆等错误。正确引文还需支持相应事实，不能把另一个年份的真实句子判为支持。

这10题是已看过的定向开发题；每条件仅一次生成，非日期模型别名和温度0仍可能有服务或采样波动。只报告观察到的成对改善与退步，不宣称泛化准确率或稳定显著收益。结果若无提升也完整保存，本轮不根据输出继续修改提示词或重新挑样本。

下一步优先由实际剩余错误决定。年份元数据属于独立后续实验，本轮不实施。最终99题仍保留到完整方案冻结后评估。
