# RRF 融合实验：排名改善没有转化为完整证据收益

2026-09-22，已完成51题开发集对照。当前结论是**保留Dense＋边界补全，暂不采用RRF替换它**。RRF与分数融合都已实现和实际评测，不把未获主要指标收益的尝试写成成功优化。

## 改了什么

新增[融合模块](<../experiments/retrieval/fusion.py>)，比较两种算法：每路分数min-max归一化后各占50%，以及按名次累计 `1/(60+rank)` 的RRF。它们使用相同的正文BM25前64块和保存的Dense前64块，统一对并集评分并截取64块。缺席某一路时该路贡献为0；同分按Chunk ID排序。参数在评分前冻结，没有扫参。

新增[本地BM25适配](<../experiments/retrieval/bm25_worker.py>)：使用现有ES索引的content_ltks字段和RAGFlow分词。当前标题字段使用自定义similarity，故没有将它混入标准BM25。这一路没有复制原生RAGFlow完整的全文查询构造器；原生Hybrid单列为系统参考。两种新融合方法之间才是严格的融合算法对照。

新增[实验入口](<../experiments/evaluation/fusion_experiment.py>)：先冻结配置与代码，再保存两路候选；先写排序和上下文选择，最后加载金标评分。没有改线上RAGFlow或生成链路。

## 实际结果

固定1000篇 / 3205块、51道开发题、每题2560 cl100k参考Token。以下为全部原始参考片段的完整覆盖题数，不是问答正确率。

| 方法 | 按排名装入 | 加入已冻结的边界补全 |
| --- | ---: | ---: |
| 正文BM25 | 43/51 | 45/51 |
| Dense | 44/51 | **48/51** |
| 归一化分数融合 | 44/51 | 47/51 |
| RRF | 44/51 | 47/51 |
| 原生Hybrid，系统参考 | 43/51 | 46/51 |

RRF相对分数融合：7题的完整证据前缀提前，1题推后；前缀倒数均值0.7039→0.7330，文档MRR@10从0.9510→0.9608。但文档Recall@5从100%降到99.02%，最终完整覆盖的题目集合完全相同。不能只挑MRR来宣布整体提升。

两路并集的无预算严格覆盖上限为49/51，与Dense相同，没有找回新的缺失参考；融合截到64块后变为48/51。两种融合＋边界补全均相对Dense＋边界补全少覆盖med-017，没有新增完整题。

## 为什么没有采用

med-017的核心金额1350元仍排在首位，但实施时间和地区说明在Dense第58名，未进入BM25前64。它在分数融合完整并集中变为第83名、RRF第91名，被64截断。此前边界补全能取到它；融合之后已不在可用候选中。这是融合与后续上下文补全的相互影响，不是生成错误，也不能说核心金额因此答错。

med-018的完整证据前缀从Dense第34名提前到RRF第7名，说明排序确有改善；但按排名装入时两者仍未完整，边界补全时两者都已完整，未形成新增覆盖。固定预算、整块大小及选择规则都会影响排序改善能否转化成最终收益。

完整59条不完整上下文及全部前缀变化均已保存在逐题诊断（本地归档：`experiments/results/private/rrf-fusion-dev51-v1/analysis.json`，未收入本备份）。报告包含BM25单路的med-026、029退步和RRF的替代来源Recall退步，没有删除负面结果。

## 验证与限制

51次本地BM25查询全部成功，未调用Embedding、Rerank或生成模型，索引状态与旧快照一致。24项针对性测试通过；独立核验10332个融合分数、255条排名、510条上下文、700次参考片段覆盖；204条控制记录与旧实验相同。新进程重放的主要输出逐字节一致。

只有6个政策组且多次用于开发，不能将本轮差异当作泛化结论。RRF与分数融合的逐题完整覆盖相同，bootstrap的[0,0]也不证明算法普遍等效。qrels尚未穷尽，不计算把未审核当错误的Precision。只测一个预定的加权基线，不推断RRF优于所有加权方案。99题测试集没有运行。

复现命令、配置、逐题文件、成本和所有指标见完整实验报告（本地归档：`experiments/results/private/rrf-fusion-dev51-v1/report.md`，未收入本备份），设计依据见[冻结协议](<rrf_fusion_protocol_v1.md>)。

下一阶段最值得做的是固定相同候选的独立Rerank对照，沿用同一上下文规则；然后冻结整体方案，处理多子问覆盖与正式测试准备。当前主候选仍为Dense＋boundary及已验证的短编号引用方案。本轮不追加RRF参数搜索。

面试重点是说明如何做受控比较、如何发现排序与完整证据的取舍、为什么根据实验保留更简单的方案。RRF来自既有研究，个人工作是适配、实现、复现和分析，不能宣称提出RRF或获得问答准确率提升。
